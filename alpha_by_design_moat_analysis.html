Alpha by Design

Strategic Moat Analysis: From Framework to Defensible Competitive Advantage

Executive Summary

The Alpha by Design framework describes a comprehensive approach to belief-driven investing. But a framework alone is not a moat — it can be copied once published. This document analyzes where defensible competitive advantages can be built within the edge discovery to edge optimization pipeline.

The Core Insight The moat is not in the framework. The moat is in the aggregated, cross-firm data that the framework's implementation generates — and the structured linkage between explicit beliefs and outcomes that no competitor possesses.

What's Defensible vs. What's Not

Asset Moat Depth Rationale
The framework itself Shallow Can be copied once published
Basic tools (dashboards, optimization) Shallow Competitors can build similar functionality
Single-firm implementation Shallow No network effect; isolated value
Cross-firm benchmark data Deep Requires client base; network effects compound
Aggregated calibration models Deep Trained on outcomes across firms; improves with scale
Process → outcome correlations Deep Only knowable with cross-firm data + outcomes
Structured belief → outcome linkage Deep Unique data structure; years of historical data

Refining the Tool Layer: Not All Tools Are Equal

The summary above groups "basic tools" as shallow moat. This is true for generic functionality, but misses an important nuance: some tools encode unique methodology and require proprietary data to function. These are not easily replicated.

Three Types of Tools

Tool Type Moat Depth Characteristics
Generic Tool Interfaces Shallow Standard functionality; competitors know what to build; dashboards, basic optimization, reporting
Novel Methodology Tools Moderate Encode unique framework concepts; missing from marketplace; require understanding to replicate
ML Models Trained on Proprietary Data Deep Algorithms trained on structured belief → outcome data; cannot replicate without data

Several framework-specific tools have no market equivalent. This creates time-to-market advantage even before considering the data moat:

Several "tools" are actually tool interface + trained ML model. The interface is replicable; the trained model is not:

The Key Insight
A competitor can copy the tool interface (what it looks like, what it does). They cannot copy the trained model without the proprietary data it was trained on. The tool is the delivery mechanism; the trained model is the moat.

The Pipeline: Edge Discovery to Edge Capture

Discovery → Articulation → Transmission → Optimization → Monitoring → Harvest

At each step in the pipeline, data is generated. Aggregate that data across clients and you can build models that improve with scale. The following sections identify moat-creating opportunities at each stage.

Stage 1: Edge Discovery → Articulation

The Linkage

BBN enumeration → Red node identification → Explicit belief capture

Moat-Creating Tool: Belief Performance Database

What It Does Why It's Defensible
Links explicit red nodes to outcomes Competitors have unstructured analyst notes; we have structured beliefs
Tracks "which belief types win" by industry, thesis type Only knowable with cross-firm belief → outcome data
Learns which question paths lead to productive edge Trained on actual discovery patterns across many analysts
Example output: "Margin expansion theses in Consumer Discretionary have a 62% win rate; pricing power theses have 71%. Consider reframing your thesis."

Moat depth: Deep — No one else has structured belief → outcome data at scale.

Stage 2: Articulation → Transmission

The Linkage

Red node (belief) → Jacobian (sensitivity) → Value impact

Moat-Creating Tool: Jacobian Library by Industry

What It Does Why It's Defensible
Pre-computes "typical" ∂V/∂driver for industry archetypes Built from many company models across clients
Enables instant materiality filtering New companies benchmarked against library
Identifies "unusual" sensitivities worth investigating Anomaly detection requires baseline
Example output: "For SaaS companies, ∂V/∂NRR is typically 8x. Your model shows 2x — is that intentional or an error?"

Moat depth: Moderate — Accumulates with each company modeled; could be approximated but costly.

Stage 3: Transmission → Optimization

The Linkage

Analyst edge → PM sizing → Portfolio realization

Moat-Creating Tool: Transmission Leakage Calculator

What It Does Why It's Defensible
Measures gap between analyst edge and realized portfolio alpha Requires full pipeline data (belief → position → outcome)
Identifies WHERE leakage occurs (sizing, timing, correlation, hedging) Trained on cross-firm leakage patterns
Benchmarks against industry: "your leakage is X%; top quartile is Y%" Cross-firm comparison data
Example output: "You're capturing 55% of analyst alpha. Industry top quartile captures 78%. Your main leakage is position sizing — conviction doesn't match Ω."

Moat depth: Deep — Requires the explicit belief → outcome linkage that competitors don't have.

Stage 4: Optimization → Monitoring

The Linkage

Position → Diffusion tracking → Forward Sharpe

Moat-Creating Tool: Diffusion Signature Library

What It Does Why It's Defensible
Predicts diffusion curve given thesis type, market regime Trained on historical diffusion across many stocks
Flags "abnormal" diffusion (faster/slower than expected) Anomaly detection requires baseline

Example output: "Margin expansion theses in Tech typically diffuse 70% in 4 months. You're at month 3 with 40% diffusion — slower than normal. Investigate or hold."

Moat depth: Moderate-Deep — Accumulates over time; hard to replicate without historical data.

Stage 5: Monitoring → Harvest

The Linkage

Forward Sharpe decay → Sell trigger → Capital redeployment

Moat-Creating Tool: Harvest Optimizer

What It Does Why It's Defensible
Given diffusion state and forward Sharpe, recommends action Trained on historical harvest decisions and outcomes
Identifies "held too long" and "sold too early" patterns Cross-firm harvest performance data
Optimizes rotation to highest forward Sharpe opportunities Requires portfolio-wide forward Sharpe computation
Example output: "Your average hold past optimal harvest is 45 days, costing 30bps. Top performers exit within 10 days of optimal."

Moat depth: Moderate — More algorithmic, but cross-firm calibration data improves accuracy.

The Meta-Moat: Structured Belief → Outcome Data

The deepest moat comes not from any single tool, but from the unique data structure that the framework creates:

Typical System Alpha by Design Framework
Unstructured analyst notes Structured BBN with explicit red nodes
Position sizes based on "conviction" Sizes based on explicit edge + Ω
Outcomes attributed to "the position" Outcomes attributed to specific beliefs
"We made money" "We made money because margin belief was correct"
Why This Matters
This structured linkage between beliefs and outcomes enables:
  • Attribution: Which beliefs worked, which didn't
  • Calibration: Who's good at which belief types
  • Optimization: What articulation patterns predict success
  • Benchmarking: How does your belief → outcome correlation compare to peers
The Competitive Reality: A competitor could copy the framework and build similar tools. They would start with zero data. The existing historical data — years of beliefs linked to outcomes — can be retrospectively analyzed through this lens. That head start compounds with each new client.

The Moat Stack

↓

The deeper you go, the harder to replicate.

The Network Effect

The Flywheel More clients → More data → Better benchmarks → More value → More clients

Each new firm that joins:

  • Contributes to the benchmark pool (anonymized)
  • Gets access to better benchmarks
  • Makes the product more valuable for everyone

This is a classic data network effect moat. The value of the platform increases with each participant, creating switching costs and barriers to entry for competitors.

Strategic Recommendations

1. Share the Framework Freely

The framework is the hook, not the moat. Sharing it:

  • Establishes thought leadership
  • Educates the market
  • Creates demand for implementation
  • Attracts clients who believe in the approach

2. Build the Cross-Firm Data Infrastructure

The data is the product. Prioritize:

  • Structured belief capture (red nodes, scenarios)
  • Outcome tracking linked to beliefs
  • Anonymized aggregation across clients
  • Benchmark computation and delivery

3. Make Benchmarks a Core Product

Clients should pay for access to the comparison, not just the tools:

  • "Where do I stand vs. the industry?"
  • "What does good look like?"
  • "What specifically should I change?"

4. Accumulate Historical Outcome Data

Time is a moat. Historical data:

  • Gets more valuable over time
  • Harder to replicate (can't go back)
  • Enables predictive models that improve with scale

Summary

The Bottom Line The framework describes what to do. The moat comes from operationalizing it with proprietary data.

Layer 1-2: Shareable and buildable — the hook and basic tools
Layer 3-4: Defensible — cross-firm data and structured belief → outcome linkage

The strategic question is not "Is the framework defensible?" but rather:
"Are we building the data assets that the framework implies?"
